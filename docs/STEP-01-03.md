# Steps 1–3 checkpoint

Completed 22 September 2026. Scope: local application foundation only.

## Step 1 — tools and storage

Observed before setup: C: about 26.6 GiB free; D: about 221.8 GiB free. Existing tools: Node 26.4.0, pnpm 11.19.0 and Git 2.46.1. Docker was not found on PATH. Ubuntu is registered in WSL with its base path under the user's C: AppData directory; its actual virtual disk allocation was not established. No WSL disk was moved or expanded.

Downloaded the official portable Node 24.21.0 LTS Windows x64 archive to D: and checked its SHA-256 against the vendor's SHASUMS256.txt. The project launcher selects this runtime without changing the global Node installation.

Paths:

- Source, node_modules, Git and Next build output: `D:\Nico\DeployDock`.
- Portable Node and downloaded archive: `D:\Nico\DeployDock-Work\tools`.
- Active pnpm store/cache/state: paths in `pnpm-workspace.yaml`, under `D:\Nico\DeployDock-Work`.
- npm cache and process temporary files: set by `dev.ps1`, under that same work folder.
- First installation's default D: store was relocated to `D:\Nico\DeployDock-Work\initial-pnpm-store`; it is no longer active. Retained rather than deleting potentially reusable downloaded packages.

pnpm 11 ignores non-registry/auth settings in .npmrc. This was caught in install output, fixed using pnpm-workspace.yaml, and the subsequent install confirmed the correct active store. Existing global caches, the package-manager executable, Codex and browser-managed data remain in their existing locations; no claim that C: receives zero managed writes.

For step 4, prefer an isolated container database with its data and container disk explicitly on D:. Docker/WSL storage must be inspected/configured before using it; no database or Redis was installed in these steps. Redis is only needed when background checks are introduced.

## Step 2 — application

Next.js 16.3.5, React 19.3.0, TypeScript 5.9.3, Tailwind 4.3.3; exact transitive versions recorded in pnpm-lock.yaml. Git initialized locally on main, without creating or publishing a remote repository. Environment example contains no secrets. Development server binds to 127.0.0.1.

The native resolver's optional install script is explicitly disabled in pnpm policy; its installed platform package supports the verified lint/build checks. No blanket permission to run dependency scripts was added.

Tooling limitation: ESLint 10.11.0 failed with the installed eslint-plugin-react (`getFilename is not a function`). ESLint is pinned to 9.39.5 for compatibility. The registry marks this version unsupported. This is development tooling, not a production runtime dependency; revisit the React plugin/config compatibility before upgrading. Do not silently update it to 10.

## Step 3 — UI foundation

Implemented the approved graphite/blue palette, local system fonts, responsive sidebar/drawer, page headers, real navigation routes, overview empty state, reusable typed button/form field, shadcn component configuration, visible keyboard focus, skip link, native modal navigation, reduced-motion styling and light/dark switching.

Routes: /, /projects, /deployments, /incidents, /settings. Account/security, project creation, deployments and monitoring are explicitly not connected. No fake login, health claims or saved project records. Theme state currently lasts for the mounted page; persistent appearance preferences belong to a later step.
